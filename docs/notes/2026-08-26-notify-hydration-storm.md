# 通知中心启动灌入风暴（2026-08-26）

## 现象

每次打开桌面，通知中心里堆满「回合已完成 · 刚刚」；点「清空」后看起来立刻又回来。条目标题是历史会话（yzj 巡检、立项），不是刚结束的回合。

## 原因

`notify-inbox` 不落盘，「清空」只清当前进程内存。真正的回填来自 `diffAttention`：会话列表第一次从空/子集灌到全量时，每个新出现且 `running: false` 的行被当成「两次快照之间结束了」。于是启动、切工作区、list 重订阅都会把历史会话再推一遍，时间戳全是 `Date.now()`，所以永远显示「刚刚」。

AGENTS.md 写的契约本来就是两侧都在才出边（`true→false` / `无→有`）。实现多写了「新来且 idle = turn-done」，和契约相反。

## 修法

`diffAttention` 只认 survivor：

- before 缺席或空 → 首样，零边
- 新 id → 列表灌入，零边
- 同 id：`running true→false` → turn-done；`pending 无→有` → await-input

清空后不会再被灌入刷回。跨进程仍不持久化（启动本应是空的）。

## 不做什么

不把 inbox 落盘。用户要的是「不要每次打开都是旧会话」，不是「记住我清过」。落盘还会把已清的历史在换机器/重装后复活。
