# Electron 加载 0.1.2 Web 一次性 token

0.1.2 起 `dsh web` 的 index 要一次 loopback `?token=` 兑换持久 cookie。无 token 的
`GET /` 恒 401。壳原先探 `GET /` 的 2xx、再 `loadURL(http://127.0.0.1:port)`，
升到这档 runtime 会卡在就绪探测，即便放行也进不了页面。

sidecar stdout 改走 pipe 再 tee 到原日志文件（文件 fd 会全缓冲，父进程看不到
`dsh web:` 行）。就绪条件改成解析该行的回环 URL；窗口加载这条 URL。日志与
诊断里的 token 写成 `<redacted>`。e2e 探针用 `URL.searchParams` 叠加 `e2e=1`，
不再拼 `/?e2e=1` 以免打坏已有 query。

0.1.2 删掉了 `settingsNamespace()` / `installSettingsSection`：namespace 直接写合法字符串，
section 挂在 `settings.installSection`。`dsh-web-search-toggle` 0.1.4（以及
mcp-settings / reasoning-efforts）跟着改。安装副本仍是旧版时，source sidecar
加载 `~/.dsh-desktop/plugins/dsh-web-search-toggle` 会直接崩；下一轮 desktop
资源包按 tarball hash 覆盖该目录。

源码 fallback 的 sidecar 默认走本机 `node`，不再默认 Electron-as-Node：同一棵
checkout 用 host Node 会打印 `?token=`，用 Electron-as-Node 时这行变成不带 token
的 `dsh web: http://127.0.0.1:<port>`，窗口无法兑换 cookie。要共用一份 Node 时再
设 `DSH_ELECTRON_ONE_NODE=1`。

`dsh-send-while-running` 本轮不卸。

0.1.2 删掉了 ApiProxy。`prepare-runtime.mjs` 的 `FORK_MODIFIED` 必须跟
`node scripts/publish-fork.mjs --list` 一致：卸 `@deepseek-ai/dsh-host-apiproxy`，
加入 `@deepseek-ai/dsh-api-session-controller`。名单仍写旧包时，组装会在
`npm view @crazx/dsh-host-apiproxy@0.1.2-alpha.3.zw.1` 上直接失败（rc.19）。

切运行面原先 `loadURL(http://127.0.0.1:<port>)`，丢掉 sidecar 打印的 `?token=`，
0.1.2 立刻 401。窗口必须加载 `waitReady` 返回的那条 URL。旧 runtime 仍打印
不带 token 的 `dsh web:` 行时，解析器接受裸回环地址，有 token 行时优先 token。

`dsh-client-runtime` 在 0.1.2 已删。`WEB_SEARCH_TOGGLE_RUNTIME_PEERS` 里缺的
peer 跳过，不再整进程扔掉。

fork 的 `publish-fork` 只发源码改动包。组装按包从 `revision.ref` 的 zw 层向下
找已发布版本，未改动的包继续用上一层，不必 11 包齐发同一 zw.N。
